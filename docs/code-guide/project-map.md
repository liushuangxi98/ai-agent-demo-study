## 3. 先牢牢记住几条分界

1. **创建模型客户端不是发送请求。**真正的模型请求发生在 Agent 循环、反思或事实提取的 `invoke()`。
2. **启动同步不等于每轮重新入库。**启动和上传会同步原件；每轮问题仍要做查询向量化和检索。
3. **模型提出工具请求，Python 才执行。**模型不会自己运行 `calculator()`。
4. **原始聊天按用户和会话分，画像只按用户分。**新建会话继续共享画像，知识文档则是全项目共享。
5. **遗忘画像不删除聊天。**旧原话仍在数据库和网页聊天记录中，模型需要按状态和时间理解。
6. **Reflection 默认关闭。**开启后检查一次、最多重写一次，失败沿用草稿并显示状态，不表示已经确认答案正确。
7. **检索距离不是回答准确率。**图里的 `0.8` 是代码默认的余弦距离过滤阈值。

## 4. 图与代码的关系

这是一份 **2026-10-22 的源码快照**，覆盖 `agent_demo/` 的所有生产类和函数，以及网页、评测入口。每个定义的路径、起止行号、完整源码都从实际文件提取；图中步骤说明根据对应代码编写。启动图中的配置检查发生在创建 `Settings` 时：`__post_init__()` 最后调用 `validate()`，通过后才进入 `AgentApp` 初始化资源。

页面图已对应整理后的 `app.py`：公共函数、操作处理和页面绘制分别摆放，末尾的 `main()` 把它们串起来。源码只保留核心注释。侧栏从顶部开始显示，会话操作和运行信息直接可见，只有“知识库管理”默认收起。

用量图对应新增的 `usage.py`：直接读取问答、反思、记忆提取返回的用量，加到当前会话上轮累计，整轮只计一次时间；`usage_json` 保存本轮与累计，网页直接展示。

图中展示的是源码默认配置，不会读取 `.env`，也不会显示你的密钥、真实聊天或上传资料。操作图只是在查看说明，不会执行项目函数或调用模型。

后续修改代码时，需要同步更新这份图；它不会在浏览器里自动读取最新 `.py`。知识库中的多 Agent、Harness 等学习文章也没有被当作项目已实现能力画进去。
